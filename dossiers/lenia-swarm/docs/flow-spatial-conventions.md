# Flow coordinates and the reference regression

Flow uses array-axis order throughout the native integrator. For mass shaped
`[batch, sx, sy, channel]`, flow component 0 advances `sx` and component 1
advances `sy`. A positive linear ramp has a positive Sobel derivative (8 for
unit spacing). Flow ascends growth potential and descends mass density, with
the configured density gate determining the mixture.

The earlier implementation reversed both Sobel signs and built its transport
position grid in the opposite axis order. The author uses default NumPy/JAX
`meshgrid` (`xy`) and then stacks `[Y, X]`; the native helper already uses `ij`
indexing and must stack `[X, Y]`. Metal reproduced the same cross-axis transport.
This creates diagonal anisotropy even after a single step. A transpose test
alone misses it: the crossed-axis operator commutes with transposition.

The correction changes trajectories. Earlier seeds, search scores and capacity
results describe the earlier dynamics and must retain their executable/source
provenance. Replay them before interpreting them under the corrected engine.
Positive obstacle *height* now produces negative growth potential; signed
user-supplied growth-potential fields retain their literal sign. The additive
QD24 update does not use this transport operator and is unchanged.

## Checks

`FlowLeniaSpatialConventionTests` checks signed ramps and transport of a unit
impulse on both axes, with rectangular grids and wall/torus boundaries.
`FlowLeniaInteractiveMetalTests` checks quarter-turn and reflection symmetry for
MLX/Metal with fixed and embedded parameters, and
`FlowLeniaBackendConformanceTests` runs the author's trajectories through MLX,
Metal and the C engine. The pre-correction engine fails the ramp, transport and
symmetry checks.

The fixture `Tests/LeniaCoreTests/Fixtures/flowlenia-author.json` was generated by
[the author's code at commit dce428c](https://github.com/erwanplantec/FlowLenia/tree/dce428c6b0c5079a06e5606fb7b5ac1fe1323bc5),
using JAX 0.6.2 and Equinox 0.12.2 on CPU. It contains an asymmetric two-channel
input and the full fields after one and eight steps, plus all parameters.
Native comparison uses the matching Colab kernel profile, per-channel alpha,
zero-padded gradient, wall boundary, and unclipped pre-integration flow.
This checks a matched configuration; it does not equate every named native
profile with the author's current defaults.

Regenerate from a clean checkout of that reference commit:

```sh
uv run --with jax==0.6.2 --with equinox==0.12.2 python analysis/generate_flow_reference_fixture.py \
  --reference-checkout /path/to/FlowLenia \
  --output Tests/LeniaCoreTests/Fixtures/flowlenia-author.json
swift test -c release --filter 'FlowLeniaSpatialConventionTests|FlowLeniaBackendConformanceTests'
```

The full validation also found and aligned three backend details: Flow channel
sums use explicit Float32 reduction instead of potentially reduced-precision
matmul; MLX excludes the same external food/chemotaxis channels from density as
Metal; and the embedded-parameter weighted average uses the same added epsilon
in both backends, including nearly empty cells. Positive circular obstacle
heights lower the growth potential. These are covered by the reference,
repulsion, search-food and search-mutation tests.

The selected validation run passed 76 tests. Both MLX execution paths, Metal and
the C engine matched the author fixture with maximum absolute field error below
3.85e-6 at one and eight steps. These are short-horizon numerical checks, not a promise of
identical long trajectories on every platform.

## One step, three backends

The same Flow Lenia step runs on MLX, on Metal and in a C engine on the CPU,
and they share their inputs: every backend takes kernel spectra from
`compileKernels` or `compilePopulationKernels` in `Core/FlowLenia.swift`, which
build them with `flowLeniaKernelDistance` and `flowLeniaKernelSpectrum`. The
sensorimotor paper step builds its kernels with the same two functions, and the
MLX transport and the convention tests take cell centres from
`flowLeniaPositionGrid`. Metal and C never build a position grid, because they
transport by integer source offsets plus the clipped flow.

| | MLX | Metal (`metal-full`) | C (`cpu`) |
|---|---|---|---|
| Entry | `FlowLeniaBatched`, `FlowLeniaParamsBatched` | `FlowLeniaMetalFullStateRunner` | `FlowLeniaCPUStateRunner`, `Sources/CFlowLeniaCPU` |
| Floats | fp32 MLX arrays | fp32, compiler options from `MetalPipeline.makeLibrary` | fp32, no contraction, 16-lane vectors, its own `exp`, radix-2 FFT with Double twiddles rounded to Float |
| Convolution | `MLXFFT` of the mass times the spectra | `MetalSpectral` | in-engine FFT |
| Torus | periodic Sobel, wrapped sources | the same | the same; half the shorter side must exceed `dd` plus the maximum advection |
| Wall | zero-padded Sobel; the transported centre is clipped to `[sigma, side - sigma]` in absolute coordinates | zero-padded Sobel; the source offset is clamped to `[sigma - 0.5 - src, side - 0.5 - sigma - src]` and wrapped sources are skipped | Metal's clamp and rounding; the shorter side must be at least `2 dd + 1` |
| Scope | every mode and operator | transport modes with embedded parameters (`avg` or `stoch` mixing, `avg` alone for one channel), food and wall masks | transport modes with fixed parameters and wall potentials; no food, chemotaxis or wall masks; sides must be powers of two of at least 16 |

The two wall clamps agree in exact arithmetic. MLX clamps the absolute position
and Metal the offset, so their results differ in the last bits at wall cells,
and the C engine copies Metal's form. The C engine sums every cell in a fixed
order whatever the thread count, so on one machine it gives the same bits for
any partition, and it is written so that other machines give the same bits as
well.

The tests that pin each piece:

| Test | Pins |
|---|---|
| `FlowLeniaSpatialConventionTests` | Sobel sign and axis order, impulse transport on rectangular wall and torus grids (MLX) |
| `FlowLeniaBackendConformanceTests` | the author fixture through MLX, Metal and C below 1e-4; ramps, impulses and random patches on 64x32 and 32x64 torus and wall grids, MLX against Metal and C below 1e-4; C against Metal over 300 steps on 10- and 20-kernel torus and 128x64 wall runs, relative to Metal's own one-ulp sensitivity; Swift kernels and Metal mass against `Fixtures/flowlenia-metal-torus.json` |
| `tt_backend/tests/test_metal_reference.py` | the float64 numpy reference in `tt_lenia/numpy_ref/metal.py` against the same Metal fixture below 1e-5 |
| `FlowLeniaCPUGoldenTests` | C field hashes after 1, 8 and 32 steps on 32x32 and 64x32 torus and 32x32 and 32x64 wall grids, from inputs built without MLX; runs without Metal |
| `FlowLeniaInteractiveMetalTests` | symmetry under quarter turns and reflections; the C simulator against Metal through circular wall-potential branches |

A uniform ramp is unstable under this step (a one-ulp change grows about
threefold per step), so the ramps are compared for three steps and the other
small fields for eight. A backend that swaps grid axes or flow components fails
every non-square case at the first step: swapping the C engine's flow
components moves the ramp fields by 0.39.
